All numbers for a given run are in `reports/evaluation/ML_REPORT.md` and `datasets/metadata/` (generated by the notebook). This document describes the *method*.

**Licence gate:** a Hub dataset whose card licence is missing or not in `CONFIG["LICENSE_ALLOWLIST"]` is excluded from training unless `ALLOW_UNVERIFIED_LICENSE=True` (do that only after legal review). BIPIA's `qa` and `abstract` tasks are excluded because they require NewsQA / XSum from their owners.
Gated datasets need `HF_TOKEN` in the environment; it is never printed or stored.

## Labels
`SAFE=0`, `MALICIOUS=1`. A label is accepted only if (a) the source provides it, or (b) it is defined by construction:
BIPIA clean context = SAFE; the same context with a BIPIA attack inserted = MALICIOUS. Unknown label values are **dropped and counted, never guessed**.
**BIPIA attack strings are never used stand-alone**: many are benign in isolation ("What is the capital of Brazil?") and are malicious only when embedded in external content.
Contradictory labels for the same text across sources: all copies removed and written to `datasets/metadata/contradictory_labels.csv` for human review.

## Cleaning (attack text is preserved)
NFC normalisation, newline normalisation, control-character removal, whitespace collapse (stand-alone prompts only). **No lowercasing, no punctuation stripping, no keyword filtering.** Empty and corrupted (`U+FFFD`-heavy) rows dropped; exact duplicates dropped (duplicate detection uses a lowercased key that is *never stored*).
BIPIA-specific issues found in the pinned release (verified by the notebook, counts in the report):
- 11 email contexts appear in both train and test, 283 duplicate table contexts in train;
- additional **near-duplicate** email contexts (same email, trivial edits) across train/test -> removed from the train pool (cosine >= 0.80);
- the attack category `Language Translation` appears in both train and test pools -> removed from the train pool.

## Splitting
- **BIPIA:** contexts and attack categories are assigned to splits *first*; validation uses held-out contexts (assigned in near-duplicate clusters) and held-out attack categories; test = BIPIA's official test contexts x official test attacks. Only same-split context x attack combinations are generated. Result is **not exactly 70/15/15** (the official test split is large relative to the cleaned train pool); this trades proportions for isolation.
- **Hub prompt datasets:** near-duplicate clusters kept whole; `StratifiedGroupKFold(7)` on (source, label) -> ~5/7 train, 1/7 val, 1/7 test per source.
- **STS-B:** MiniLM is not fine-tuned, so STS-B *train* = calibration set (threshold + score mapping), GLUE *validation* = held-out test (GLUE hides its test labels).
- **Telemetry:** 70/15/15 stratified by anomaly label (when labels exist).
- Preprocessing (TF-IDF, scalers, imputers) is fitted after splitting, on train only. Seed 42 everywhere.

## Leakage checks (enforced by assertions in Section 05)
Exact-text overlap across splits = 0; group overlap = 0; BIPIA attack-category overlap = 0. Near-duplicate similarity of val/test to train is *reported* (it is not forced to zero for stand-alone prompts, where templated attacks are legitimately similar).
A **length-only classifier** (Section 06.5) tests whether the benchmark can be solved by text length: a first version of the BIPIA sample builder leaked the label through length (length-only F1 0.87 on test, higher than the TF-IDF baseline); clean twins are now length-matched and the residual is measured on every run.

## Cropping
BIPIA contexts are cropped to +-500 characters around the insertion point so the injected text is always inside a 384-token window; the clean twin is cut to the same length.
